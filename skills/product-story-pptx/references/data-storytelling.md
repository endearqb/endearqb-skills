# Storytelling with Data 图表规范

> Skill 路径：`product-story-pptx/references/data-storytelling.md`

产品 deck 中的图表不是分析工作台，而是论证页面。观众不应先研究图，再猜你的结论；**标题就是答案，图表是证据。**

本规范把 Storytelling with Data 的核心流程落成 spec 字段、脚本默认值和 lint 规则。

## 1. 先理解语境

作图前回答：

- 受众是谁？
- 他们已经知道什么？
- 他们需要做什么决定？
- 哪一条数据足以改变这个决定？
- 什么比较基准才公平？

如果无法用一句话写出图表结论，先不要画图。

## 2. 图表选择

| 分析意图 | 首选 | 何时使用 |
|---|---|---|
| 类别比较 | `bar` | 类别少、标签短 |
| 类别比较，标签较长 | `hbar` | 4–8 个类别 |
| 时间趋势 | `line` | 时间连续、强调方向与拐点 |
| 两个时间点变化 | `slope` | 起点/终点、前后变化 |
| 精确位置或排名 | `dot` | 想弱化面积、强调位置 |
| 一个核心数 | `big_number` 页面 | 数字本身是记忆锚点 |
| 前后状态 | `compare` 页面 | 重点是机制差异而非连续数值 |

禁止：

- 饼图、环图。
- 3D 图表。
- 双 Y 轴。
- 装饰性雷达图。
- 多层堆叠面积图。
- 仅为“丰富视觉”而出现的仪表盘。

这不是说这些图永远不能用，而是产品演示场景中它们通常增加解码成本、削弱单一结论。

## 3. 消除杂乱

`chart_swd.py` 默认：

- 去除图表边框。
- 去除大部分网格线。
- 单序列不显示图例。
- 使用直接标注。
- 轴线退为 `rule` 色。
- 其他数据退为 `neutral_data`。
- 来源放在左下。
- 示例数据放右上角标。

人工仍需检查：

- 类别 ≤ 8。
- Series ≤ 3。
- 小数精度统一。
- 单位写在 `unit`，不要每个标签重复长说明。
- 缩写对目标受众可理解。
- 图内不重复页面标题。

## 4. 聚焦注意力

每张图最多高亮 2 项，优先 1 项。

```yaml
highlight: ["找文档"]
```

- Bar/hbar/dot：填 category 名。
- Line/slope：填 series.name。
- 第一个高亮用 `accent`。
- 第二个高亮用 `accent_soft`。
- 其余数据统一灰色，不使用彩虹色盘。

没有 highlight，通常意味着还没决定这张图想让人看什么；lint 会警告。

## 5. Action title

差：

- 调研结果。
- 用户数据。
- 使用情况。

好：

- 员工每周花 5.2 小时找信息。
- 上线 8 周后，重复提问下降 62%。
- 使用率增长来自一线团队，而不是管理层推动。

Action title 应优先写结论，时间、样本量与口径放 subtitle、annotation 或 source。

## 6. 直接标注

- Bar：数值写在柱端，类别直接写在轴旁。
- Line：系列名与末值写在线尾，避免图例来回对照。
- Slope：左端写系列名与起点，右端写终点。
- Dot：数值写在点右侧。

直接标注减少眼睛在“图例—颜色—数据”之间往返。

## 7. 诚实的轴

### 柱状图

必须从 0 开始。柱长编码的是量，截断轴会夸大差异。

### 折线图

不要求强制从 0 开始，但：

- 必须保留足够上下文。
- 时间间隔真实等距。
- 若轴截断可能误导，标题或注释说明。
- 不通过拉窄范围制造“暴涨暴跌”。

### 百分比

- 区分“增长 10%”与“增长 10 个百分点”。
- 分母和样本量必要时写入 annotation/source。
- 0–100% 的量若只展示局部，要有明确理由。

## 8. 数字格式

- 千位分隔：`12,400`。
- 小数默认 0–1 位，不展示虚假精度。
- 百分比：`62%`，不写 `62.00%`。
- 倍数：`3.4×` 或 `3.4x`，全篇统一。
- 时间：`3 分 15 秒`，不要混用 `3:15` 与中文格式。
- 货币、能耗、流量等必须带单位和口径。

## 9. Big number

Big number 页只保留：

1. 一个数字。
2. 一个说明它代表什么的 action title。
3. 一个比较基准。
4. 一个来源。

```yaml
- type: big_number
  number: "3.4×"
  title: "找到答案的速度是原来的 3.4 倍（示例数据）"
  caption: "中位数从 11 分钟降到 3 分 15 秒"
  source: "示例数据，仅用于版式演示"
  is_example: true
```

单独的“大数字 38%”没有意义；必须知道相对谁、在什么口径下、意味着什么。

## 10. Annotation

Annotation 不是重复标题，而是指出阅读方式：

- “四成时间花在找文档”。
- “以 W1 为 100 归一化”。
- “增长主要发生在第 3–5 周”。

一张图最多一条主要 annotation。更多解释交给讲者或拆页。

## 11. 渐进揭示

复杂图可以分两页：

- 页 1：全体数据灰色，建立基准。
- 页 2：位置不变，高亮关键系列并改变 action title。

这比在一页放五个箭头、四段注释更有效。

两页仍计入“连续图表页 ≤ 2”；之后必须换气。

## 12. 数据来源与示例标记

`source` 必填，至少能让团队内部追溯：

- 数据库/报表名称。
- 时间范围。
- 样本量。
- 负责人或链接标识。

示例、合成或虚构数据必须：

```yaml
is_example: true
source: "示例数据，仅用于版式演示；交付前替换"
```

不得用看似精确的示例数字冒充真实产品效果。

## 13. 颜色与可访问性

- 颜色不单独承担语义：同时用直接标签、字重或位置。
- 高亮色与背景保持足够对比。
- 非高亮数据仍可读，但不应与重点竞争。
- 红/绿对照时，同时写“过去/现在”“未通过/已通过”，避免仅靠色觉区分。

## 14. Spec 示例

```yaml
- type: chart
  bleed: none
  energy: 3
  mood: 被说服
  label: 试点结果
  title: 上线 8 周后，重复提问下降 62%（示例数据）
  chart:
    kind: line
    data:
      categories: [W1, W2, W3, W4, W5, W6, W7, W8]
      series:
        - name: 重复提问 / 周
          values: [100, 94, 81, 70, 62, 51, 44, 38]
        - name: 总提问 / 周
          values: [100, 103, 108, 110, 112, 115, 114, 116]
    highlight: [重复提问 / 周]
    annotation: 以 W1 为 100 归一化
    source: 示例数据，仅用于版式演示
    is_example: true
```

## 15. PNG 与原生图表的取舍

当前实现使用 Matplotlib 渲染 PNG：

优点：

- 跨 PowerPoint/LibreOffice 样式稳定。
- 直接标注、字形、颜色与去杂乱规则可控。
- 不依赖 Office 原生图表默认主题。

限制：

- 图表不是 PowerPoint 原生可编辑数据系列。
- 修改数据应回到 YAML，重新构建。

若项目要求交付后由业务人员直接编辑图表数据，应扩展 native chart renderer，并保持同样的 action title、聚焦、来源和 QA 规则。

## 16. QA

- 标题是否已直接说出结论？
- 3 秒内眼睛是否落到正确数据？
- 去掉高亮后，是否仍能看懂整体？
- 是否存在不必要网格、边框、图例或颜色？
- 柱状图是否从 0 开始？
- 单位、精度与比较基准是否一致？
- Source 是否真实可追溯？
- 示例数据是否明确标注？
- 图表之后是否安排换气？
