# 视觉语言：主题、字体、色彩与图像

> Skill 路径：`product-story-pptx/references/visual-language.md`

“有 taste”不是多用效果，而是整份 deck 对同一个气质做出稳定选择：相同的视觉距离、字体性格、光线、颜色职责和留白节奏。

## 1. 先选设计方向，再选颜色

不要先问“喜欢蓝色还是橙色”。先判断产品与场合：

- 精确、开发者、工业、AI 工具：克制深色、高对比、界面局部。
- 消费品、生活方式、品牌故事：暖白、编辑感、触感照片。
- B2B SaaS、数据与决策：明亮背景、强信息层级、少量品牌色。

本 skill 内置三套主题。

## 2. 内置主题

### `ink`

气质：深色、精确、发布会感。

适合：

- AI、开发者工具、工业软件、硬件发布。
- 有高质量产品图或 UI 截图。
- 需要明显峰值和舞台感。

关键 token：

- 背景 `#0E0F12`
- 文字 `#F4F3EF`
- 强调 `#FF5A36`

### `paper`

气质：暖白、编辑、品牌叙事。

适合：

- 消费产品、设计产品、生活方式。
- 有纪实摄影、材料细节、人物故事。
- 希望像杂志而不是软件界面。

关键 token：

- 背景 `#F6F3EC`
- 文字 `#1B1B1B`
- 强调 `#1F4FD8`

### `signal`

气质：纯白、高对比、理性决策。

适合：

- B2B SaaS、解决方案汇报、数据较多。
- 需要打印、邮件阅读或明亮会议室投影。

关键 token：

- 背景 `#FFFFFF`
- 文字 `#0B0C0F`
- 强调 `#00A676`

## 3. 主题选择矩阵

| 内容特征 | 推荐 |
|---|---|
| 大量暗色产品截图 | ink |
| 真实纪实照片、品牌故事 | paper |
| 主要是图表、流程与决策 | signal |
| 深色会场大屏 | ink |
| 日间会议室、需要打印 | signal / paper |
| 用户已有严格品牌规范 | 复制最接近主题后覆盖完整 token |

不要一份 deck 同时使用两套主题。章节变化通过 bleed、明暗比例和图片完成，不通过换模板完成。

## 4. 字体系统

默认：

- Latin：Inter。
- CJK：Noto Sans CJK SC。
- 回退：Arial / Microsoft YaHei。

最多两族字体 + 一个 CJK 回退。当前实现为跨环境稳定，主要使用一套 sans-serif 体系，通过字号、字重、空间而不是多字体制造层级。

### 字号阶梯

| 角色 | 默认 pt |
|---|---:|
| Cover title | 54 |
| Section title | 44 |
| Statement | 40 |
| Page title | 32 |
| Quote | 30 |
| Subtitle / big number caption | 20 |
| Body / bullet | 18 |
| Flow label | 16 |
| Attribution | 14 |
| Caption | 13 |
| Kicker / flow desc | 12 |
| Footer | 10 |

一页最多使用 3 个主要字号。页脚与来源不计入主要层级。

### 字重

- Action title：Bold。
- Kicker：Bold + 轻微字距。
- Body：Regular。
- 高亮数据：Bold。
- 不用斜体作为主要强调，尤其中文。

### 中英混排

- 中文与英文数字保持同一基线。
- 产品名、API、单位不强行全角化。
- 中文标题中的英文单词不要自动全部大写。
- 数字与单位之间全篇统一，如 `5.2 h` 或 `5.2 小时`。

## 5. 颜色职责

采用“主背景 / 结构中性 / 单一强调”的职责分配，而不是平均分配颜色。

### 60 / 30 / 10

- 约 60%：背景与大面积图片基调。
- 约 30%：surface、文字、结构线与中性数据。
- 约 10%：accent，用于唯一重点。

这不是像素级计算，而是防止所有颜色同等用力。

### 强调色只能表达

- 当前流程步骤。
- 图表 highlight。
- CTA。
- 章节转折。
- 关键数字或动词。

不要把 accent 用在：

- 每页固定装饰线。
- 所有图标背景。
- 无意义的圆点、边框、页码。
- 每一条 bullet。

### 第二强调色

`accent_soft` 仅用于：

- 图表第二高亮。
- 同一视觉中层级更弱的关联项。

全篇不要发展成第二套品牌色。

## 6. 对比度

目标：

- 普通正文与背景 ≥ 4.5:1。
- 大标题与背景 ≥ 3:1。
- 次级文字不能浅到投影后消失。

发现对比不足：

1. 提高文字/背景对比。
2. 减少图像复杂度或加 scrim。
3. 调整位置。
4. 不用描边、发光、重阴影补救。

## 7. 图片语言

### 产品图

- 统一相机高度与焦段。
- 统一光源方向。
- 背景干净，但不要每张都悬浮在渐变球上。
- 产品特写展示材料、接口或关键交互，不拍无意义全景。

### UI 截图

- 先决定要证明哪个操作，再裁切。
- 保持文字可读，必要时局部放大。
- 去除浏览器杂项、个人账号和敏感数据。
- 同一 deck 使用一致圆角、边框、背景和缩放。
- 不把整个 dashboard 缩成邮票。

### 场景图

- 展示产品发生作用的环境，而不是泛化“商务成功”。
- 人物姿态自然，优先纪实而非摆拍。
- 人物视线朝向文字或产品。

### 实拍与生成图

生成图必须标注为合成占位或概念示意。交付给外部客户前，确认使用权、品牌与真实性要求。

## 8. 图标

图标不是默认视觉解决方案。

仅在以下场景使用：

- 3–4 个并列、确实需要快速区分的功能。
- 用户已有统一图标系统。

规则：

- 单一线性或单一实心风格。
- 单色。
- 等尺寸、等描边。
- 不放进五颜六色圆形底。
- 没有一致图标集时，用编号与短标题更好。

## 9. Shape 语言

- 圆角矩形：用于流程节点与 UI 模拟，圆角轻微。
- 细线：用于分割与基线。
- 圆形：仅用于编号/里程碑。
- Chevron：仅用于方向。
- 不使用阴影作为层级默认手段。
- 不使用玻璃拟态、霓虹发光、3D 挤压。

## 10. Motif

一份 deck 可以有一个重复母题，例如：

- 左下角的低位标题。
- 细网格仅出现在愿景页。
- 产品轮廓被边缘裁切。
- 章节页的短横线。
- UI 中一致的橙色状态点。

母题应与产品机制或品牌相关。不要把“每页一根彩色竖线”当作设计系统。

## 11. 接入品牌

### 轻量覆盖

在 spec：

```yaml
deck:
  theme: signal
  brand:
    accent: "#0057FF"
    color_block: "#0C1B33"
    font_latin: "Arial"
    font_cjk: "Microsoft YaHei"
```

适合已有一个主品牌色，但没有完整设计系统。

### 完整主题

复制 `design-tokens.yaml` 中最接近的一套，新增 key，并定义：

- background
- surface
- text / text_muted
- accent / accent_soft
- neutral_data
- rule
- color_block / color_block_text
- scrim_dark / scrim_light
- text_on_dark_scrim / text_on_light_scrim

品牌色饱和度很高时，背景仍用中性色；不要把品牌色稀释成满篇浅色卡片。

## 12. 去除 AI 味

常见 AI slide 痕迹：

- 每页 3–6 张同款圆角卡片。
- 渐变紫蓝背景 + 发光球。
- 每条 bullet 配一个无意义图标。
- 大标题下固定一根彩色短线。
- 图片、图表、流程都被塞进卡片。
- 所有页面内容居中。
- 泛化 stock 图与空洞 slogan。

修正方式：

- 让真实产品证据承担视觉。
- 一页只保留一个主结构。
- 用留白和比例做层级。
- 让页面之间有强弱，而不是每页都“高级感”。

## 13. 一致性检查

- 全篇是否只使用批准的字体、字号和字重？
- Accent 每页是否只承担一个重点？
- 图片是否统一色温、光线和视觉距离？
- 截图是否统一边框与裁切？
- 流程节点与图表是否共用同一 token？
- 页脚与页码是否固定？
- 章节峰值与普通内容页是否有明显强弱？
