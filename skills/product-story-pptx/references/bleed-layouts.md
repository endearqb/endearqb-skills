# Bleed 图片版式系统

> Skill 路径：`product-story-pptx/references/bleed-layouts.md`

Bleed 指图像、色块或视觉对象触及并延伸到幻灯片边缘，取消“图片装在相框里”的感觉。它把图像从配图提升为环境，因此具有很强的情绪权重。

**正因为强，才不能滥用。** 当一半以上页面都是满版图，full bleed 不再是峰值，只剩视觉噪音。

## 1. 模式总览

本 skill 支持 10 种模式：

| 模式 | 画面关系 | 常见用途 | 推荐 energy | 文字负荷 |
|---|---|---|---:|---|
| `none` | 所有视觉位于安全区 | chart、flow、compare、statement | 1–3 | 中等 |
| `full` | 图片覆盖整页 | cover、reveal、vision、closing | 4–5 | 极低 |
| `overlay` | 满版图 + 半透明文本面板 | 图片复杂但需要较多解释 | 4–5 | 低 |
| `partial-left` | 图片从左、上、下出血 | quote、feature、人物/场景 | 3–4 | 中低 |
| `partial-right` | 图片从右、上、下出血 | feature、界面或产品特写 | 3–4 | 中低 |
| `half` | 右侧精确半页图片 | 功能 hero、截图展示 | 3–4 | 中等 |
| `half-top` | 图片贴顶，占上半屏 | 空间全景、章节开场、场景建立 | 3–4 | 中低 |
| `half-bottom` | 图片贴底，占下半屏 | 产品落地、人物证言、结果收束 | 3–4 | 中低 |
| `edge` | 产品从右下边缘溢出 | 设备/包装/3D 产品特写 | 4 | 低 |
| `color-block` | 整页强色，无图片 | 章节、转折、唯一强声明 | 3–5 | 极低 |

坐标以 `assets/layout-registry.yaml` 为准。

## 2. Full bleed

适用：

- 开场定调。
- 章节首次 reveal。
- 愿景与新常态。
- Closing CTA。

规则：

1. 图片至少 1920 px 宽，推荐 2400 px 以上。
2. 必须指定 `scrim: dark | light | gradient`。
3. title + body 中文合计不超过 24 字，英文不超过 12 词。
4. 文字进入预设安全区，不追着图像主体移动。
5. 用 `image_focus` 控制裁切，保留主体或负空间。
6. 不在人物脸、产品 logo、关键 UI 上压字。
7. 不连续三页 full。

Full bleed 的设计目标不是“让图最大”，而是让**主张与画面成为同一件事**。

## 3. Overlay

满版图本身信息丰富，直接压字会失去可读性时使用半透明面板。

适合：

- 复杂工厂、地图、仪表盘、多人场景。
- 需要一段简短解释而非一句话。

规则：

- 面板宽度不超过页面 55%。
- 面板与图像之间不加阴影；靠透明度和空间分层。
- 面板内仍然保持低文字量。
- 不把 overlay 当作“满版图上再塞一张白卡”的万能修补。

## 4. Partial left / right

这是产品 deck 中最稳定的图文节奏：一半感性，一半理性。

### 选择方向

- 人物视线向右：人物放左，文字放右。
- UI 的关键操作在左：图片放右，让关键区域靠近文字边界。
- 产品外形朝向某侧：让产品“面向”文字，而不是逃离画面。

### 连续页面

两个 feature hero 连续出现时左右交替：

```text
partial-right → partial-left → edge/none
```

不要机械地左右左右十页；第三页应改变信息结构，而不是只镜像。

### 页脚

当图片占据左侧且背景较亮时，页脚标签应移动到文字列；`build_deck.py` 已对此做自适应。

## 5. Half

`half` 是精确 50/50 结构，适合屏幕截图、UI、产品局部与三条以内能力说明。

规则：

- 图片侧不叠字。
- 文字侧不额外套卡片。
- 图像关键内容应在被裁切后仍完整。
- 如果截图中的文字小到投影时看不清，改成局部放大或重新构图，不要把整张 dashboard 硬塞进去。

### 上下半屏

`half-top` 和 `half-bottom` 用于需要横向景深、但又不能牺牲文字可读性的页面：

- `half-top` 的文字放下方，适合先看环境、再落到结论。
- `half-bottom` 的文字放上方，适合先给判断、再用画面承接。
- 图片必须真正触达左、右和对应的上下边缘。
- 页脚始终留在文字半屏，不能压在复杂图片上。
- 相邻两页不要连续使用同一上下方向。

## 6. Edge crop

让产品从页面边缘被裁切，可制造“对象比画布更大”的力量感。

适合：

- 硬件、包装、工业设备、3D 渲染、手机或屏幕特写。

规则：

- 裁掉主体不超过约三分之一。
- 裁次要边缘，不裁 logo、接口、屏幕或人物脸。
- 全篇使用 1–2 次足够。
- 不适合数据图、流程图和密集截图。

## 7. Color block

没有合适图片时，强色比低质量图库图更诚实。

适合：

- 章节断点。
- 概念反转。
- 一个不可拆分的主张。
- 全篇唯一的“品牌色爆发”。

规则：

- 一份 deck 最多一页把高饱和强调色铺满全页；其余 color-block 可用深色中性背景。
- 不叠加装饰线、渐变球、网格噪点等多重效果。
- 文字越少越好。

## 8. Energy 与 bleed 对照

| Energy | 首选 | 可选 | 通常避免 |
|---:|---|---|---|
| 5 | full、overlay、color-block | edge | none + 普通标题正文 |
| 4 | half、partial、edge、full | color-block | 密集 bullets |
| 3 | none、partial、half | color-block | 无缘由的 full |
| 2 | none | partial quote | full、overlay |
| 1 | none | 极克制的 quote | 任何强 bleed |

这是软映射。比如一张低能量、全屏黑白纪实照片可以非常有效，但必须有明确叙事理由。

## 9. Scrim 规范

| Scrim | 用途 | 建议 |
|---|---|---|
| `gradient` | full 页，文字在下方 | 默认；从文字侧 82% 不透明渐隐到远端 5% |
| `dark` | 复杂或亮色图片 | 约 55% 黑色覆盖 |
| `light` | 暗色图片、品牌要求深色文字 | 约 62% 浅色覆盖 |
| `none` | 仅限文字不在图片上 | full/overlay 禁用 |

文字与背景对比至少达到普通正文 4.5:1、大标题 3:1 的可读性目标。

发现文字不清晰时的修复顺序：

1. 调整 scrim。
2. 调整 `image_focus`。
3. 改变文字区域或 bleed 模式。
4. 最后换图。

不要直接给文字加粗黑描边或大阴影。

## 10. Cover crop 与焦点

所有图片都以 cover 方式裁切：保持比例，裁掉超出目标框的部分，绝不拉伸。

`image_focus`：

- `center`：主体居中。
- `left/right`：保留对应侧内容。
- `top/bottom`：保留对应垂直区域。

焦点不是“把主体挪到文字下面”。正确做法是优先选择本身有负空间的图。

## 11. 图片方向

同一份 deck 应统一：

- 色温：冷、暖或中性。
- 饱和度：全彩或统一低饱和。
- 光线：软光、硬光或高对比。
- 摄影距离：纪实广角、产品中景或微距特写。
- 截图处理：统一圆角、边框、背景与缩放比。

实拍图和 3D 渲染可以共存，但必须有意区分：例如“现实场景用实拍、未来愿景用渲染”。无规则混用会像素材拼盘。

## 12. 缺图降级策略

```text
真实产品图 / 截图
→ 合成但明确标注的产品示意
→ color-block / 大字 statement
→ 抽象几何（与产品机制相关）
→ 最后才是图库图
```

分辨率不足时，应从 `full` 降级为 `half/partial/edge`，而不是放大模糊图。

## 13. 禁用意象

除非产品本身与其直接相关，不使用：

- 握手。
- 灯泡代表创意。
- 齿轮代表流程。
- 靶心代表目标。
- 伸手触碰悬浮界面。
- 假笑会议与统一西装团队。
- 无意义的蓝色粒子、发光大脑、机器人握手。

## 14. QA 清单

- Full 页是否有足够分辨率、scrim 与负空间？
- 人物视线或产品朝向是否指向文字？
- Half 页截图的关键文字能否在投影距离看清？
- Edge crop 是否裁到了关键部件？
- 相邻 hero 页是否重复同一构图？
- Contact sheet 中能否明显看出峰值，而不是每页都在抢戏？
