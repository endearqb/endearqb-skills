# 问题清单 Schema 与合并规则

供 Auditor 写 digest、Orchestrator 合并问题清单时统一格式与裁决规则。

## digest 单条字段（Auditor 产出）

```
- 位置: L42–43               # 行号区间或可定位的锚点片段
- 原文片段: "<≤15 字摘录>"    # 仅供定位，不要整段复制
- 类型: C-11 先破后立         # 透镜组字母 + base 分类编号 + 名称
- 严重程度: 硬失败 / 高 / 中 / 语境相关
- 为什么: <一句话理由>
- 建议动作: 删除/压缩/落地/补源/降级/换主语/合并/拆分/重排
```

每个 dim digest 末尾加一行自评：`本透镜命中 N 条（硬失败 a / 高 b / 中 c / 语境相关 d）`。

## _status.json（Auditor 产出，供监控）

```json
{ "dim": "dim03", "lens": "C-structure", "done": true, "hits": 7, "hard_fail": 0 }
```

## 严重程度定义（四级，全流程统一）

- **硬失败**：事实、引文、含义、来源、限制、安全边界出错。必修。
- **高**：明显损害可信度的客服腔、模糊权威、空洞拔高、自我旁白、邀约收尾。通常修。
- **中**：重复的模板结构、词簇、节奏、格式。密度高时修。
- **语境相关**：被动、副词、破折号、设问、三项列表、第一人称。仅在无功能或过量时修。

## 合并规则（Orchestrator 在 Phase 5 执行）

### 1. 去重

同一位置被多个透镜命中：合并为一条，类型字段并列标注（如 `C-11 + D-18`），严重程度取**最高**的那个。

### 2. 密度合并（同类型多次命中提级）

当同一类型（或同一句型模式）在全文中被命中 **≥3 次** 时，不按逐条计算，合并为一条**系统性问题**：

- **合并方式**：取所有命中中严重程度最高的那一级，再**上调一级**（语境相关→中，中→高）。上调上限为"高"——不会跳到"硬失败"，硬失败仅保留给事实/安全/法律类错误。
- **合并后的条目格式**：

```
- 位置: 全文（L12, L45, L78, L102, L135, L201, L258, L290）
- 原文片段: "不是X，而是Y"（×8）
- 类型: C-11 先破后立 [系统性]
- 严重程度: 高 ← 原为"中"，因 ≥3 次密度触发提级
- 为什么: 单次使用无问题，但全文 8 次构成结构性重复，读者可感知的 AI 模式感
- 建议动作: 保留 2–3 处最有力的，其余改写为其他表达方式
```

- **适用场景举例**：
  - "不是X，而是Y"出现 ≥3 次 → 合并为 C-11 系统性
  - "**启示是：XXX**"在表格中 ≥3 行使用相同句型收尾 → 合并为 B-07 系统性（表格内重复句型同样适用，因为读者是连续扫描的）
  - "闭环""沉淀""落地"等领域术语在 ≤500 字区间内出现 ≥3 次 → 合并为 D-18 系统性
  - 整句加粗（`**>10字**`）出现 ≥5 处 → 合并为 F-32 系统性

- **占名额方式**：合并后的系统性问题只占 1 条名额，而不是 N 条。这正是密度合并的价值——用 1 条配额覆盖 N 个位置。

### 3. 解决透镜间冲突

冲突按 base 技能优先级裁决，顺序固定：

```
事实/安全/法律 > 用户明确要求 > 原文含义/数据/引文/论证 > 体裁/受众/作者声音 > 去 slop 规则 > 表面流畅
```

常见冲突与裁法：

- dim04 词汇说"删某词"，dim01 事实说"该词是术语/承载事实" → 事实优先，**保留**。
- dim06 节奏说"合并碎句"，dim05 语气说"此处停顿是作者声音" → 若有作者样本佐证，声音优先，保留停顿。
- dim03 结构说"删路标词"，但删后逻辑关系丢失 → 原意优先，改用准确连接词而非裸删。

冲突的裁决结果写进 `issues.md` 对应条目的备注。

### 4. 排序与收敛

按严重程度排序（硬失败 > 高 > 中 > 语境相关），同级按位置先后。**砍到收敛上限**——收敛上限随文档长度浮动：

```
收敛上限 = min( max( ceil(字数 / 1000) × 3, 5 ), 20 )
```

即每 1000 字允许约 3 条问题，下限 5 条（短文不低于此），上限 20 条（防止过度修改）。举例：500 字文章 → 5 条；2000 字 → 6 条；6000 字 → 18 条；10000 字 → 20 条（触顶）。

这是硬性收敛判据，对齐 base 技能"只抓最影响读感的问题、不全量去味"的精神，同时避免长文档因配额不足而漏掉系统性问题。被砍掉的低影响项写入 `race_log.md` 一行（位置 + 类型 + 砍除理由），不进入重写。

收敛优先顺序（决定砍谁留谁）：

```
1. 事实与含义错误
2. 空段、空结论、模糊来源
3. 模板结构、客服语气
4. 句法与节奏
5. 单词与标点
```
