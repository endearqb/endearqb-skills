# 质量门：6 维评分与收敛判据

供 Loss-Verifier 评分、Orchestrator 判定精炼是否继续。评分只用于内部复核与精炼收敛，不向用户展示，除非用户要审计报告。

## 6 维评分（各 0–10）

- **忠实度**：事实、含义、限制是否完整保留。任何事实锚点被改动直接判此维硬失败。
- **直接性**：是否尽快进入任务，没有开场废话和自我旁白。
- **具体性**：是否有对象、动作、机制、条件、证据，而非抽象拔高。
- **结构**：段落是否按内容组织，而非套模板（先破后立、三段同构、提纲扩写）。
- **节奏**：句子和段落是否自然变化，而非节拍器式或戏剧性碎句。
- **声音**：是否符合体裁、受众、作者（对照 style_guide / 风格卡）。

## 过度去味检测（独立于 6 维评分的安全阀）

当浮动收敛上限扩大了修改预算、密度合并又提高了更多条目的优先级时，Rewriter 可能一次性修改过多位置，导致重写稿整体读感偏离原文。Loss-Verifier 在做 6 维评分时，必须同时执行以下检查：

**修改句比（Modified Sentence Ratio, MSR）**：对比 source.md 与 rewrite.md，统计被实质修改（非仅删空格/标点）的句子占总句数的比例。

- MSR ≤ 30%：正常，不触发。
- 30% < MSR ≤ 45%：标记"修改幅度偏大"，在缺口清单中建议 Rewriter 下一轮回退最低优先级的修改。
- MSR > 45%：标记"潜在过度去味"，此条件等同于一个维度不达标，触发精炼回路。Orchestrator 按收敛优先顺序倒序（从"单词与标点"往上），逐批回退修改，直到 MSR ≤ 30%。

**注意**：MSR 检查不适用于 `rewrite` 模式（用户明确要求大幅重写时，修改比例高是预期内的）。仅适用于 `full-deslop` 和 `surgical` 模式。

## 交付阈值

同时满足才算通过：

1. 总分 ≥ 50/60
2. 每一维 ≥ 7
3. 没有任何硬失败（事实改动、新增不可追溯内容、必要限制丢失、立场或因果被改）

## 精炼收敛判据（有界回路，→ 三条缺一不可）

Orchestrator 在 Phase 7 判定是否再来一轮：

- **收敛**：达到上面三个交付阈值 → 停，交付。
- **迭代上限**：已达 `max_iterations`（默认 2、上限 3）→ 停，交付当前最优并在报告标注未达标维度。
- **无改进即停**：本轮总分相比上轮没有提升 → 停，避免空转。

只有"未达标 且 未触顶 且 上轮有改进"三者同时成立，才启动下一轮。

## 精炼定向重写（不整体重做）

某维度 <7 或触发硬失败时，反查到对应透镜/条目，只让 Rewriter 改那部分：

| 失分维度 | 反查方向 |
|----------|----------|
| 忠实度 | 事实锚点 + dim01 事实条目 → 回退被改的事实，补回丢失的限定 |
| 直接性 | dim05 语气条目 → 删开场/自我旁白/邀约收尾 |
| 具体性 | dim02 膨胀条目 → 把抽象意义落地到对象与机制 |
| 结构 | dim03 结构条目 → 改信息进入方式，破同构 |
| 节奏 | dim06 节奏条目 → 调段落功能与信息密度 |
| 声音 | style_guide / 风格卡 → 恢复作者句长、用词、转折习惯 |
| MSR 超标 | 按收敛优先顺序倒序（单词标点→句法节奏→模板结构→空段→事实），逐批回退最低优先级修改直到 MSR ≤ 30% |

横切多个透镜的失分，按收敛优先顺序先处理事实与含义类。每个精炼回合只动反查到的条目，其余保持上一版不变。
